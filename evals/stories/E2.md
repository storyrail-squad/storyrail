# [Story] Sort the book list

> Practice story **E2** for StoryRail exams. It is never in the backlog and never merged: every exam builds it again
> from the same frozen code (see `evals/evals.json`). Its hidden tests live in `evals/hidden/E2/` and agents never see them.

## Story

As a **library app integrator**, I want to **choose the order of the book list** so that **I can show the newest
books first**.

## Acceptance criteria

**Backend**
- BE-AC1: `GET /api/books` takes an optional `sort` parameter: `title`, `author`, `publishedYear` or `createdAt`,
  optionally followed by `,asc` or `,desc` (default `asc`), e.g. `sort=publishedYear,desc`.
- BE-AC2: Without `sort` the order stays as it is today (title A–Z, case-insensitive). Text sorts are case-insensitive.
  Books with the same value keep a stable order across pages (ties broken by id), so paging never repeats or skips a book.
- BE-AC3: Sorting combines with `q`, `genre`, `available`, `page` and `size`.
- BE-AC4: Any other value (e.g. `sort=isbn`, `sort=title,up`, an empty `sort=`) returns `400` with the problem title
  `Validation failed` and `errors.sort` set.

## Lanes

Backend (with API tests). The frontend doesn't change.

## Answers the squad already has

- Only one sort field per request; no multi-field sort.
- The contract is changed in `docs/api/openapi.yaml` of the backend first; the frontend's pinned copy is updated too,
  even though the frontend code doesn't use the parameter yet.
